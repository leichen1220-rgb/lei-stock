## 收盤資料（V1.1.1）

上市股票及 ETF 同時讀取證交所原始 CSV 與 OpenAPI，以內容的交易日期選擇較新來源，同日優先 CSV。上櫃使用櫃買 OpenAPI。單一來源失敗仍可使用另一來源；全部失敗或資料倒退則保留先前價格與原日期。

- 原始 CSV：https://www.twse.com.tw/exchangeReport/STOCK_DAY_ALL?response=open_data
- OpenAPI：https://openapi.twse.com.tw/v1/exchangeReport/STOCK_DAY_ALL
- 櫃買：https://www.tpex.org.tw/openapi/v1/tpex_mainboard_daily_close_quotes

政府資料開放平臺的個股日成交資料標示每 1 日更新，但未查到此 OpenAPI 固定發布時刻的官方承諾。下載檔名與下載時間不作為報價日期。2026-10-12 下午實測原始 CSV 內容為 1151012，OpenAPI 為 1151008，故不能假設兩者同步。

GitHub 排程於台灣時間每日 07:43、週一至週五 14:43–19:43 每小時抓取，實際執行可能延後。「更新收盤價」重新讀取已發布快照，不會立即觸發背景抓取，也不是盤中即時行情。


## 脫敏公開持股（V1.2.0）

固定網址：`https://leichen1220-rgb.github.io/lei-stock/portfolio.json`。
**首次成功發布後才會建立此檔案。尚未設定後端時網址為 404，不能當成空持股。**

- 網站持股總覽與後端共用 `supabase/functions/_shared/portfolio-core.js` 的股數加總。只有現股及股票股利影響股數；以十進位加總避免浮點殘值。保留代號原文、小數股數，剔除股數恰為 0 者；負持股或缺少名稱會阻止發布。
- 登入後成功同步（包括新增、修改、刪除交易及股票名稱儲存）會呼叫 `portfolio-publisher`。可在持股總覽的「公開持股同步」重新發布。未登入不呼叫，讀取失敗不發布。直接在資料庫或其他工具修改，需下次網站同步後才發布；沒有背景掃描私人交易的排程。
- 函式驗證登入 JWT，限制一個設定好的帳號，並帶同一個使用者 JWT 和 owner 條件，透過原本 RLS 讀取最少欄位。沒有 service-role key、沒有新增資料表／SQL／RLS 或匿名 SELECT。拒絕客戶端提供持股、路徑或帳號。
- 寫入 GitHub 的檔案內容一律重新建立 `{code,name,shares}`，沒有其他欄位、時間戳或包裝物件。GitHub 憑證僅在 Supabase 函式 secrets，瀏覽器及公開 JSON 沒有憑證。
- 每次發布先取 GitHub 檔案 SHA，再讀最新持股。衝突會重新讀取；內容相同不寫入；失敗保留上次檔案。私人帳本儲存不受發布失敗影響。
- GitHub Pages 發布及 CDN 更新可能需數分鐘，不能由本專案設定 Pages 的 HTTP 快取標頭。程式讀取時使用 `cache: 'no-store'` 並附 `?v=當下時間戳`，例如 `portfolio.json?v=1791794711108`，避開重用舊網址快取。JSON 本身是純陣列，Content-Type 由 Pages 依 .json 提供。
- 公開 repo 的 Git 歷史會保留歷次三欄持股快照；不只當下持股可見。此公開功能不應加入任何私人交易欄位。

### 一次性後端啟用

1. GitHub Settings → Developer settings → Fine-grained personal access tokens：建立只可存取 `leichen1220-rgb/lei-stock` 的 token，repository Contents 設 Read and write。不要把 token 貼進聊天、程式碼或前端。
2. 股票網站登入後，持股總覽 → 公開持股同步 → 首次設定資訊 →「複製後端帳號限制設定」。取得 `PUBLIC_PORTFOLIO_OWNER_ID` 的值。
3. Supabase **目前這個共用專案** `vhkupxpaojlzfokmdfup` → Edge Functions → Secrets：設定 `PORTFOLIO_GITHUB_TOKEN`（步驟 1）和 `PUBLIC_PORTFOLIO_OWNER_ID`（步驟 2）。`SUPABASE_URL` 及 `SUPABASE_ANON_KEY` 使用 Supabase 函式內建環境變數，無需把交易登入密碼交給 GitHub。
4. 在電腦取得最新 repo，登入並只部署這一個函式（不要執行 db push，也不需要套用任何 SQL）：

   ```sh
   git clone https://github.com/leichen1220-rgb/lei-stock.git
   cd lei-stock
   npx supabase login
   npx supabase functions deploy portfolio-publisher --project-ref vhkupxpaojlzfokmdfup
   ```

   若已有 repo，先更新既有 repo 即可。平台 JWT 驗證保持開啟；函式內再驗證 JWT 和唯一帳號限制。此部署不修改劇單或股票資料表權限。
5. 回股票網站重新整理並登入，在持股總覽按「重新發布持股」。成功後等 Pages 完成發布，開公開網址加新時間戳，確認純 JSON 與網站持股一致。

測試：`node --test tests/*.test.cjs`，含匿名／其他帳號拒絕、僅三欄、欄位洩漏檢查、十進位抵銷、股數小數、ETF 前導零、寫入衝突重讀與相同內容不提交。尚未部署時，測試以模擬 Supabase／GitHub 驗證流程；不能冒稱遠端已啟用。

`.nojekyll` 確保 Pages 原樣提供共用程式與 JSON，避免 Jekyll 略過 `_shared` 目錄。


## 每股配息（V1.2.1）

交易明細顯示每股配息；沒有儲存的每股配息時，以股息總額（扣匯費前）除以除權息日前股數推算，標示「推算」。當天現股買賣會讓配息資格不明，因此不猜測；同日股票股利不納入本次現金股息的推算基礎。原 Excel 的每股配息先前沒有獨立匯入，歷史推算不是公告值或已核對值。

在 Supabase SQL Editor 執行 `sql/08_dividend_rate.sql` 一次後重新整理，即可在新增／編輯交易記錄每股配息及配息股數。新增兩個 nullable 私人欄位，不改任何交易、RLS 或匿名權限。輸入每股配息和配息股數後會帶出總額，總額仍可依實際通知更正；清空選填欄位不會清掉原總額。匯出 Excel 與 JSON 備份保留兩個欄位；公開 portfolio.json 仍僅有 code、name、shares。Excel 未記錄率仍用原表累計股數推算，實領金額公式直接使用已存總額扣匯費，避免重算率改變歷史收支。


### V1.2.2 實領股息

交易明細外層的股息欄改為實領股息＝原總額－匯費，篩選／排序也使用同一實領金額；原總額仍可從進階篩選選擇。編輯仍保留每股配息、配息股數、原總額與匯費。匯費空白顯示待填匯費，明確輸入 0 則實領等於總額；不把未填當作已確定免匯費。


### V1.2.3 緊湊篩選

縮小篩選控制項、條件列內距與間距，限制桌面欄位寬度，說明文字預設收合。手機條件自動換行並保留 36px 高度；不改篩選條件或交易表寬度。


## 借券收入（V1.3.0）

新增交易別借券收入，金額／扣費／入帳日／確認狀態／備註沿用收入記錄欄位，沒有股數、成交價或每股配息。實領收入＝總額－扣費；納入原 Excel 累計收支、含收入淨投入與累計損益，股息和借券收入各自統計。移動平均買賣成本試算仍只計買賣，不把借券收入列為卖出獲利。持股股數及公開三欄 JSON 不受影響。

先在原 Supabase 專案執行 `sql/09_stock_lending_income.sql` 後重新整理網站。SQL 擴充既有交易別檢核，借券收入另有金額／零股數限制；不改 RLS／資料表授權，不自动修改任何既有交易。新增的啟用狀態 RPC 只有 authenticated 可執行，不開放 anon。

交易明細的「整理舊出借收入紀錄」列出備註含出借收入／借券收入的現金股息，按鈕會先列出日期、代號與金額請你核對，再逐筆依登入帳號轉換。保留總額、扣費、入帳日與備註，移除不適用的配息率欄位；失敗時說明已轉換筆數。可手動編輯其他借券收入。原 Excel 批次暫存匯入流程仍保留原三種交易別規則；本次不更動舊暫存／正式匯入 RPC。

Excel 主表 F 欄忠實輸出借券收入，N 改為實領收入、AC 改為收入總額；M 每股配息在借券列留白，D 股數留白，E 總股數保持，O 收支與 T 損益計入借券收入。總覽分列累計淨股息與累計借券淨收入；總額／扣費／日期／備註完整保存。JSON 備份保留原記錄資料。


## V1.7.0：統一持股總覽與浮動試算

- 總覽一檔一列：現有股數、移動平均持股均價、最近收盤、未實現、已實現買賣、已入帳淨收入、累計總損益。可搜尋並切換持有中／已出清／全部。
- 已入帳以既有入帳確認旗標或已填扣費判定；待入帳金額在展開內容另列，不計新版總損益與整檔回本價。原始交易與 Excel 明細公式保持原記錄；Excel 總覽採新版欄位。
- 展開可修改賣出股數、價位、標的種類，查看預估實收、費稅、這次損益、剩餘股數及賣後總損益。部分賣出的剩股按最近收盤估值，未視為已實現。
- 持股回本價按移動平均成本；整檔回本價含歷來買賣與已入帳收入。每批都賺價依 FIFO 追蹤剩餘批次，以最高含費單位成本作門檻，要求本次淨收入超出最高成本門檻至少 0.01 元。費稅按賣出股數分攤。
- FIFO 賣出先扣最早買進，股票股利按當時股數比例加入每批，成本保持；分割、減資等必須有相應正確記錄。FIFO 不改寫原紀錄，亦不取代主表的移動平均成本。
- 回本價依可調手續費、折扣、最低手續費、稅率及取整方式試算，向上對齊股票／ETF 檔位，未套當日漲跌停。券商實際金額與資格仍須核對。
- 右下角非模態小工具可跨頁使用、收起；桌機可拖動，手機為可捲動的底部面板。費率設定保存在本機，交易與持股內容不另寫入。
- 本版不新增 SQL，既有 SQL 11 的實際賣出實收欄位可繼續使用；缺值會沿用已記錄價格與費用推算。


### V1.8.0 — 買入與零股試算
- 浮動工具新增「買入」，可選「預算能買幾股」或「指定股數算費用」。股數以 1 股為單位。
- 顯示最多可買股數、成交金額、預估手續費、含費總支出、含費每股成本與預算餘額。
- 預算包含手續費，依既有費率、折扣、最低費用與取整設定計算；買入不套用賣出交易稅。零股預算不足時顯示 0 股，不收取虛構費用。
- 試算視為單筆委託，實際以券商成交及計費為準；拆單可能影響費用。只在畫面試算，不寫入交易，不需更新 SQL。



## V1.9.0：股本異動

股票明細 →「股本異動」可記現金增資認購、現金減資、彌補虧損減資、股票／ETF 分割、反分割／併股。現有股票股利功能保留。合併換股、公司分割配發其他股票、ETF 清算尚未支援，請勿套成本次分割。

### 啟用（不改既有交易）

1. 在原 Supabase 專案 SQL Editor 執行 `sql/12_stock_corporate_actions.sql`。僅建立獨立私人事件表、索引與本人存取政策；不更新／刪除／改寫任何既有買賣。可重複執行。未安裝時入口顯示尚未啟用，其他功能照常。
2. 重新整理股票網站。新事件預設「待確認」，只需代號、類型、生效日及順序；實際股數／款項可留空。富采不會被程式自動新增，也不會套公告比例估值。
3. 拿到券商實際通知後，編輯該事件為「已核對實際數字」。填異動前／後股數、畸零股數、扣費前本金／畸零股折現款和實際扣費；無費用／畸零股款須明填 0。認購填含費實付與認購股數。先按「核對異動前後」，檢查完整後續交易通過後才儲存。
4. 股數生效日和現金入／扣帳日分開；只有手動勾選已核對現金入／扣帳才變成已入帳。未收到但金額已確認的退款按應收淨額納入總損益，另外顯示待收，不灌入股息。
5. 公開持股發布也需更新函式。在電腦取得最新版 repo 後執行：

   ```sh
   npx supabase login
   npx supabase functions deploy portfolio-publisher --project-ref vhkupxpaojlzfokmdfup
   ```

   沿用原 secrets，無須重設 token；不要執行 db push。這一步只部署該函式，不動劇單或股票交易。新增股本事件後瀏覽器會送版本標記，舊後端會拒絕該請求，避免把舊算法結果重新發布；升級後仍只公開 code、name、shares。

### 計算與保護

- 事件獨立存 `stock_corporate_actions`。原始交易永不重寫；JSON／ZIP 備份包含完整事件，Excel 有獨立「股本異動」工作表與調整後總覽。
- 待確認和未到生效日的事件不套用數字；待確認事件到生效日後，該股票仍顯示沿用舊股數並標待確認，成本、估值及賣出試算停用，公開持股發布停止（原檔保留）。
- 異動在同日所有買賣之前／之後可選；多筆事件以事件順序排列。確認時核對異動前庫存，並重播所有後續事件與交易；不相符即阻止確認。日內穿插多個事件／交易尚不支援，需按實際批次另外核對。
- 現金減資的本金按剩餘股數比例從各 FIFO 批次扣除，股數依實際換發數縮放；主表維持移動平均。退本金超過主表剩餘成本時，成本降到 0，超額另列股本異動損益，並非稅務申報認定。
- 彌補虧損減資、分割／併股：未折現時成本總額保留；畸零部分按異動前後總股數比例分攤成本，折現淨額減分攤成本另列股本異動損益。費用不重複扣除。認購形成新批次。
- 新股數不能搭舊報價估值：尚無生效日以後報價時顯示缺價；跨異動日不顯示一般前日漲跌。歷史最高買價比較會依生效事件換算；新填目標價仍由你自行核對。
- 股息每股推算改用異動後庫存；同日異動或待確認事件會停止猜測配息股數，已記錄的每股配息不改。
- 有股本異動的股票，其 Excel 原始明細舊版股數／累計公式會標「股本異動請看持股總覽」，不輸出錯誤累計；原始成交股數、價格、費用、實付／實收、日期仍保留。其他股票匯出不變。

驗證：既有帳本測試、新增五類事件／畸零股／前後交易重播／FIFO／應收退款／公開發布測試；桌機與手機模擬保存待確認及確認分割，均未寫入原始交易表。SQL 在隔離 PostgreSQL 測試重複安裝、確認欄位限制及兩帳號 RLS；未連到你的 Supabase 執行。



## V1.10.0：集中新增、精簡股本異動與金額互算

- 股票明細只留「＋ 新增」入口，選交易紀錄或股本異動／查看紀錄才顯示編輯區，儲存／取消後收起，平常不佔明細空間。
- 股本異動前庫存按日期及同日順序從帳本帶入；主要欄位只顯示所選類型需要的資料。畸零股、費用、入帳與同日順序收在「其他細節」；無畸零股／費用預設 0，預覽時仍逐項列出。遇同日買賣會主動展開順序設定；先前待確認事件未處理時不猜庫存。
- 買進：成交金額＋費用＝實付；賣出、現金股息、借券收入：總額－費用＝實領。填任兩項補第三項，0 是有效數字，空白不是 0。已自動計算的欄位標色，來源修改後更新；手填三項矛盾會提示，改動金額後不允許帶矛盾數字儲存。
- 可選「改算總額／費用／實付實領」指定要覆算的欄位；選取代表明確重算該項。成交金額平常由股數乘成交價帶入；總額由金額互算得出且未填成交價時，會依股數反推成交價並標示自動計算。已有成交價與總額不符時不默默覆蓋，需核對或清空成交價後重算。
- 金額加減乘使用十進位整數運算，不擅自依券商費率猜費用或做整元取整；反推成交均價可含小數，實付／實收仍為記錄的交割金額。依券商通知核對。
- 成交金額與實領收入是表單輔助欄位，不新增資料庫欄位：買賣沿用 paid_cost／sale_net_received／trade_fees；股息與借券沿用 dividend_gross／wire_fee。不需新 SQL 或後端重部署。
- 開啟舊紀錄僅帶入已存資料，不自動補寫；只改備註保留原金融欄位。移除舊版改股數／成交價／費用就清空實際交割金額的行為，改由互算或不一致提示協助核對。全部變動均需你按儲存才寫入。
